# Interface polish gate

Polish follows navigation recovery and session verification, not new model work.
The first visual pass should keep the existing static-site architecture.

## First pass

- Put weekly/start-sit and waivers ahead of draft-only tools in in-season navigation.
- Keep one league selector per page. Separate selected league from connected user
  and roster; do not make editing a username look like a successful connection.
- Use one compact status area for connection, selected week, data freshness, and
  actionable blockers. Keep detailed provenance available without dominating results.
- Put recommendations or the reason advice is withheld before research details.
- Group draft-only and unsupported tools explicitly; never imply that discovery
  enables advice for an unconfigured league.
- Review small-screen tables, form wrapping, keyboard focus, and error recovery
  on rendered pages before choosing spacing or typography changes.

## Acceptance checks

Check Gabagool and FAM independently, then simultaneously in two tabs. Verify
discovery round trips, automatic/manual week selection, refresh failures, filters,
exports, and restored sessions. Check ESPN and invalid URLs for honest recovery.
Inspect desktop and narrow-screen layouts and complete a keyboard-only core flow.

Passing unit fixtures is not a visual or accessibility sign-off. Do not remove
read-only, freshness, coverage, or experimental-model warnings merely to simplify
the page. No league mutations, claims, or bids are needed for these checks.
